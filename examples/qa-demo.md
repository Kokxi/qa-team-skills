# /qa 示例：统一入口 — 支付接口全量回归

>
> 展示 `/qa` 统一入口的自然语言→多步任务编排→记忆管理全流程。

## 原始输入

```
/qa
对支付接口做全量回归并输出缺陷报告
```

```
## 任务执行计划

1. 【第一步】/qa-case：设计支付接口全量回归测试用例
```

> 用户确认后，逐步骤执行，步骤间数据自动传递。

### 第三步：用例设计（节选）

**PAY-TC001：余额支付正常流程**（核心层/P0/场景法）
- 步骤：1. 选择余额支付 2. 确认支付 3. 网关返回成功
- 预期：订单→支付成功，余额扣减

**PAY-TC002：银行卡支付正常流程**（核心层/P0/场景法）
- 步骤：1. 选择银行卡支付 2. 跳转银行网关 3. 支付成功
- 预期：订单→支付成功

**PAY-TC003：支付网关超时处理**（核心层/P0/场景法）
- 步骤：1. 发起支付 2. 网关无响应超过30s
- 预期：订单→支付超时，触发补偿

**PAY-TC004：并发支付同一订单**（核心层/P1/错误推测）
- 步骤：1. 两客户端同时支付同一订单
- 预期：仅一笔成功，无重复扣款

## 使用技巧

1. **任务描述要包含范围和目标**："/qa 对支付接口做全量回归并输出缺陷报告" 比 "/qa 测试支付" 更精准
2. **多步任务自动传递数据**：前一步的评审问题/用例信息会自动注入下一步，无需手动复制粘贴
3. **中间步骤可打断**：每一步执行前都会输出执行计划，用户可以确认或调整
4. **记忆模块自动沉淀**：所有产出自动写入 `memory/data/`，后续任务可复用

# qa-team-skills 使用手册

> 版本：v1.5.4 | 统一入口 /qa + 8 个标准化指令 + 记忆模块 + 自动规划

## 1. 技能简介

`qa-team-skills` 将 AI Agent 嵌入软件测试标准流程，提供统一入口 `/qa` + 8 个标准化指令：

| 指令 | 定位 | 适合谁 |
|------|------|--------|
| `/qa` | **统一入口**：自然语言→任务解析→指令路由→记忆管理 | 所有角色 |
| `/qa-prd` | 需求评审 | 测试工程师、测试经理 |
| `/qa-case` | 测试用例设计 | 测试工程师 |
| `/qa-agent` | AI 智能体专项测试 | 测试工程师 |
| `/qa-bug` | 缺陷分析 | 测试工程师、开发 |
| `/qa-report` | 报告生成 | 测试工程师 |
| `/qa-team` | 团队管理 | 测试经理 |
| `/qa-explore` | **探索性测试（v1.5 新增）** | **测试工程师** |

## 2. 安装

qa-team-skills 核心为纯 Prompt 工程，无外部依赖。提供三种安装方式：

### 方式一：手动复制（通用）

| AI Agent | 全局安装路径 | 项目内路径 |
|----------|-------------|-----------|
| **Claude Code** | `~/.claude/skills/` | `.claude/skills/` |
| **OpenCode** | `~/.config/opencode/skills/` | `.config/opencode/skills/` |
| **GitHub Copilot** | — | `.github/skills/` |
| **OpenAI Codex CLI** | `~/.agents/skills/` | — |
| **Cursor** | — | `.cursor/skills/` |

```bash
# 示例：全局安装到 Claude Code
cp -r qa-team-skills ~/.claude/skills/
```

### 方式二：一键安装

```bash
npx skills add Kokxi/qa-team-skills
```

自动检测当前 Agent（Claude Code / OpenCode / Codex / Cursor 等），安装到正确位置。

### 方式三：ClawHub 安装

```bash
clawhub install qa-team-skills
```

## 3. 指令详解

### 3.1 `/qa-prd` — 需求评审

**场景**：评审会上快速发现需求问题。

**输入**：
| 字段 | 必填 | 说明 |
|------|------|------|
| 产品/模块 | ✅ | 明确评审范围 |
| 需求内容 | ✅ | 粘贴 PRD 原文 |
| 关联依赖 | ❌ | 依赖的其他模块 |

**输出**：11 维度问题清单（表格，含严重程度） + 业务分层建议 + 需产品经理澄清的问题列表。

**11 个评审维度**：完整性 / 清晰度 / 可测试性 / 一致性 / 隐形需求 / 边界需求 / 性能需求 / 安全需求 / 兼容性需求 / 可维护性需求 / 业务分层。

> 新增「业务分层」维度：判断需求属于核心层（缺失产品无价值）/ 体验层（影响顺畅度）/ 增值层（锦上添花），指导后续用例设计优先级。评审报告会给出分层建议及理由。

---

### 3.2 `/qa-case` — 测试用例设计（9 种黑盒方法）

**场景**：需求评审通过后，生成标准化测试用例。

**输入**：
| 字段 | 必填 | 说明 |
|------|------|------|
| 产品/模块 | ✅ | 被测对象 |
| 需求描述 | ✅ | 功能说明 + 验收条件 |
| 评审问题清单 | ❌ | 粘贴 /qa-prd 输出，AI 不会自动读取历史对话，需手动提供 |
| 行业/合规要求 | ❌ | 仅强监管行业填写，AI 可参考 team/ 目录下的行业配置 |
| 关联系统 | ❌ | Jira/禅道编号 |

**输出**：6 种测试类型 × 9 种黑盒方法交叉矩阵生成的用例，每条含业务分层（必填）、设计方法（必填）、优先级、测试数据、预期结果。末尾有用例统计和 Jira/禅道追踪标签。

**业务分层**（每条用例必填）：核心层（缺失产品无价值）/ 体验层（影响顺畅度）/ 增值层（锦上添花）。与优先级互补——优先级回答"不执行风险多大"，业务分层回答"功能本身对用户多重要"。

**6 种测试类型**：功能 / 边界 / 异常 / 安全 / 性能 / 兼容性。

**9 种黑盒方法**：等价类划分 / 边界值分析 / 判定表 / 因果图 / 状态迁移 / 场景法 / 正交实验 / 错误推测 / 探索性测试。

---

### 3.3 `/qa-agent` — AI 智能体专项测试（16 维度）

**场景**：AI Agent 产品有传统软件没有的测试维度，需要独立覆盖。

**输入**：
| 字段 | 必填 | 说明 |
|------|------|------|
| Agent 名称/类型 | ✅ | 被测 Agent |
| Agent 能力描述 | ✅ | 工具列表、知识库、协作 Agent |
| Agent 系统提示词 | ❌ | 用于注入测试 |
| 合规框架 | ❌ | 适用法规，AI 可参考 team/ 目录下的行业配置 |
| 关联系统 | ❌ | Jira/禅道编号 |

**输出**：16 个维度 × 黑盒方法交叉矩阵生成的用例。

**16 个维度（含 RAG）**：Agent 基础功能 / 提示词安全 / 工具调用权限 / 知识库隔离 / 多 Agent 协作 / 输出安全 / 信息安全 / AI 幻觉 / AI 偷懒 / AI 稳定性 / 可控性 / 资源消耗 / 合规与伦理 / 检索准确性（RAG）/ 来源归因（RAG）/ 上下文窗口（RAG）。

> RAG 维度（14-16）仅在 Agent 涉及知识库/检索时生成，否则标注"不适用"。

---

### 3.4 `/qa-bug` — 缺陷分析

**场景**：粘贴缺陷，先评估描述质量，信息充分后再做根因分析。

**输入**：缺陷标题、复现步骤、期望结果、实际结果、报错日志（可选）、产品/模块。

**输出**：
- 第一阶段（必输出）：缺陷描述质量评估（5 维度），不达标时输出引导式补全清单
- 第二阶段（信息充分后）：根因分类 + 影响范围 + 修复建议 + 回归测试要点 + 同类缺陷预防。所有分析标注置信度（高/中/低）

---

### 3.5 `/qa-report` — 报告生成

**场景**：将测试工作数据组织为结构化报告。

**输入**：报告类型、时间段、数据来源（文本/文件）、团队/个人信息。

**5 种报告**：
| 类型 | 场景 |
|------|------|
| 日报 | 每日站会/下班前 |
| 周报 | 周会汇报 |
| 阶段报告 | 迭代结束/版本发布/里程碑 |
| 季度报告 | 季度复盘、同比环比 |
| 专项报告 | 性能/安全/兼容性专项 |

**数据来源**：直接输入一段话（AI 从非结构化文本提取数据）、上传 CSV/Excel 文件、依据 Jira/禅道等系统数据。日报/周报支持最小输入模板简化填写。

---

### 3.6 `/qa-team` — 团队管理（11 项子能力）

**场景**：测试经理汇总团队数据，生成管理报告。**纯管理定位**，支持关键词自动路由。

**V1.0.0 子能力（P0）**：
| 子能力 | 说明 |
|--------|------|
| 团队日报/周报汇总 | 多人报告合并 |
| 测试进度看板 | 各模块/人员进度，标红延期 |
| 缺陷趋势分析 | 缺陷密度/修复率/收敛趋势 |
| 团队成员产出 | 用例和缺陷按级别细化 |

**V1.0.1 新增（P1）**：
| 子能力 | 说明 |
|--------|------|
| 漏测复盘 | 线上缺陷根因归类 + 预防措施 |
| 任务分配建议 | 需求范围 + 负载 + 能力匹配 |
| 团队效能统计 | 人均指标 + 趋势同比 + 加班率 |
| 新人培训计划 | 4 周分阶段路径 + 考核节点 |
| 周会纪要 | 数据速览 + 模块进展 + 待办 |
| 准入准出检查 | 提测/发布条件清单 + 风险评估 |
| 版本质量评估 | 6 维度加权评分（满分 100）|

## 7. 记忆模块说明

`memory/` 模块是 qa-team-skills 的**长期记忆体**，让技能越用越好。

### 工作原理

```
每次 /qa 启动时：
  ① 扫描 data/products/{模块名}/ 是否存在历史数据
  ② 存在 → 生成记忆简报（含历史用例/缺陷/规范）
  ③ 不存在 → 首次使用，跳过
  ④ 执行指令时自动参考历史数据

每次指令完成后：
  ① 按产品模块写入 data/products/{模块名}/{库名}/
  ② 合并去重 → 更新 latest.json
  ③ 同步更新 summary.json 索引
```

### 存储结构

```
memory/data/products/
├── 支付接口/           ← 每个产品独立目录
│   ├── test-cases/    ← 用例库（v1.0.json + latest.json）
│   ├── bugs/          ← 缺陷库
│   ├── reports/       ← 报告库
│   ├── standards.json ← 规范库（自动沉淀）
│   └── summary.json   ← 索引文件
└── 登录模块/
    └── ...
```

### 优势
- **越用越好**：第二轮起的 `/qa` 会自动加载历史，参考上轮缺陷和规范
- **本地持久化**：纯 JSON 文件存储，内网/离线可用。写入记忆前会先询问用户确认
- **版本可追溯**：每条用例标注来源版本，支持回滚

详见 `memory/README.md`。

## 8. 安全与隐私声明

### 数据存储
- 本技能会自动将你的测试数据存储到本地 `memory/data/products/` 目录下
- 存储内容包括：测试用例、缺陷分析、评审记录、测试报告、团队数据、探索笔记、规范条目
- **所有数据仅保存在本地文件系统**，不会自动传输到外部

### 需要你确认的操作
- 每次向记忆库写入前，AI 会询问你是否确认
- 版本清理（删除旧版本文件）会先征求你的意见
- 规范沉淀（自动提取经验教训）会先询问是否写入

### 注意事项
- ❗ 不要粘贴真实的生产环境凭证、支付标识、客户个人信息或敏感截图
- ❗ 上传文件给 AI 时，文件内容会出现在生成的报告/用例中——请先脱敏
- ❗ `ci/run_llm_eval.py` 会连接外部 LLM API，运行前请使用脱敏的评测数据
- ✅ 清理记忆：删除对应 `memory/data/products/{模块}/` 目录即可

### 版本清理说明
历史版本文件（旧版 v*.json）在合并快照后会保留最近 5 个版本，更早的会由 AI 询问你后才删除。已删除版本的数据仍保留在 `latest.json` 汇总快照中，不丢失。
